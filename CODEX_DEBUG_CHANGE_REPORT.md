# Debug Change Report

## Issue

Clicking **Failed Rows** after an employee import returned a 404 even though
the backend had generated the Excel report.

## Root Cause

The import endpoint generates filenames from `new Date().toISOString()`, which
end in `Z` (for example,
`failed-employee-rows-2026-09-15T20-14-16-093Z.xlsx`). The download endpoint
validated filenames with `/^failed-employee-rows-[\\dT-]+\\.xlsx$/`; that
character class did not permit `Z`. The request therefore reached the mapped
controller but was rejected as a not-found report before the filesystem lookup.

## Files Changed

| File | Change | Reason |
|---|---|---|
| `backend/src/modules/dashboard/dashboard-employees.controller.ts` | Replaced the failed-report filename regex with one that exactly accepts the UTC ISO timestamp format generated by the import endpoint. | Allow generated report filenames through the existing safe validation and download flow. |
| `CODEX_DEBUG_CHANGE_REPORT.md` | Added this report. | Document the actual debugging work and verification performed. |

## Files Not Changed

`backend/src/app.module.ts` was inspected and intentionally left unchanged:
it already imports `DashboardModule`. `backend/src/modules/dashboard/dashboard.module.ts`
was also left unchanged because it already registers `DashboardEmployeesController`.
The report-generation service and dashboard API client were inspected and left
unchanged: they generate/pass the same filename, construct the correct route,
and supply the bearer token.

## Verification

- `pnpm --filter backend build` — passed; refreshed the compiled backend.
- Started `node dist/src/main.js` from `backend` — passed; Nest mapped
  `GET /api/v1/dashboard/employees/import-reports/failed-rows/:filename`.
- Tested the compiled controller against a generated report using its real
  stream implementation — passed; downloaded a non-empty XLSX and verified
  `Content-Type` and `Content-Disposition` headers.
- Sent an unauthenticated request to the live download URL — received `401
  Unauthorized`, confirming the JWT guard remains active.
- `pnpm --filter backend exec eslint src/modules/dashboard/dashboard-employees.controller.ts`
  — passed.

## Final Result

The existing authenticated Failed Rows endpoint now accepts the exact filename
returned by the import endpoint, finds the backend-generated `.xlsx` report,
and streams it to the dashboard download flow.
